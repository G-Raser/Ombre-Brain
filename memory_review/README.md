# 待审核记忆区 / Memory Review Queue

`memory_review/` 是 `cattea-memory-new` 的旁路待审核区，用来临时存放还没有进入 Ombre Brain 正式记忆库的新记忆候选。这里的文件只是 Markdown 草稿，不接入后端、不接入 Dashboard、不接入 MCP，也不会触发正式入库。

pending 不是正式记忆库。
pending 里的内容不会被 Ombre Brain 自动读取。
只有主人确认后，后续流程才可以把它们正式写入 buckets。

## 为什么需要待审核区

Codex、CC 酱、猫茶或其他工具以后可能从对话、规则文件、共同经历、工程记录中提取出值得长期保存的内容。如果这些内容直接写入正式 `buckets/`，容易造成误导入、重复入库、重要度膨胀，或者把临时情绪和项目过程误当成长期规则。

待审核区的作用是先把候选内容放在安全旁路里，由主人和相关角色判断是否值得入库、应该是什么类型、重要度应该是多少。这样正式库保持干净，CC 酱和猫茶也不用在额度有限时承担大量机械整理工作。

## 什么内容应该进入 pending

- 从清洗后的对话片段中整理出的长期记忆候选。
- 规则文件里可能需要长期保留的身份边界、互动规则、语言规范。
- 共同经历、重要梗、项目结论、偏好变化。
- thinking 候选摘要中值得进一步审核的内容。
- 手动整理的 seed pack 中还没有被主人确认的条目。
- 可能属于 `I` 或 `feel` 的内容，但只能作为候选，不能自动批准。

## 什么内容不应该进入 pending

- 已经明确进入正式 `buckets/` 的现有记忆。
- 临时 debug 噪音、一次性运行日志、无长期价值的报错。
- API key、token、认证配置、隐私凭据。
- 主人没有授权提取的敏感原文。
- 明显重复、明显过时、明显错误的内容。
- 会绕过主人确认、直接改变正式库行为的文件或脚本。

## pending 与正式 buckets 的区别

`memory_review/pending/` 是候选草稿区，面向人工审核；`buckets/` 是 Ombre Brain 的正式记忆库，可能被服务读取、检索和使用。pending 中的候选不等于事实记忆，不代表已经批准，也不参与 Ombre Brain 的正式召回。

主人确认前，不得把 pending 候选写入正式 `buckets/`。即使候选看起来很合理，也必须先经过审核流程，尤其是 `anchor`、`pinned`、`I`、`feel` 这类高影响类型。

## 分工原则

CC 酱额度有限时，Codex 应负责批量整理候选、统一格式、去重、标注来源、生成报告；CC 酱只做少量关键判断，例如身份边界、情感沉淀、自我描述是否准确。猫茶主库未来也可以复用同一套审核流程，把新记忆先放入待审核区，再由主人确认是否进入正式库。

## 当前阶段

本阶段没有自动入库脚本，所有候选只是 Markdown 草稿。`approved/`、`rejected/` 也只是审核状态的存档位置，不代表已经接入正式 Ombre Brain 流程。
